# Feature Specification: 面板视觉与定位修正

**Feature Branch**: `002-panel-visual-polish`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "引入显示比例换算与托盘定位，实现比例缩放正确与启动界面时位置正确而非屏幕中央，增加右上角的关闭按钮，将 PID 等杂项信息合理拆分展示在顶栏和底栏，以平衡界面观感"

## 背景与实测依据

本规格处理的四个问题都来自真实会话中的实测观察，不是假设：

| 观察 | 实测值 | 期望值 |
|---|---|---|
| 界面元素整体偏大 | Qt 报 `devicePixelRatio = 2.0` | KWin 实际输出缩放 1.5 |
| 面板出现在屏幕中央而非托盘处 | 实际 frame `(664, 237)` | `(1329, 8)` 即右上角 |
| 面板无关闭入口 | 只能点别处让面板失焦收起 | 明确的关闭按钮 |
| 信息密度失衡 | 顶栏挤着状态、URL、来源 | 状态与细节分层 |

补充约束（实测）：`QSystemTrayIcon.geometry()` 在 Plasma Wayland 恒返回 `0×0`，**托盘图标坐标不可获取**；普通窗口的 `move()` 在该合成器下不生效，`pos()` 只反映 Qt 自身记录、不代表实际落点。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 面板出现在托盘附近而非屏幕中央 (Priority: P1)

用户左键点击托盘图标，面板出现在屏幕右上角、紧贴托盘图标下方，而不是屏幕中央。

**Why this priority**: 面板出现在屏幕中央会遮挡正在看的窗口内容，而且离托盘图标很远，用户视线要跨整个屏幕。这是四项中最影响日常使用的一条。

**Independent Test**: 点击托盘图标后读取窗口实际 frame（而非 Qt 报告的坐标）；右上角锚定时 x 应接近屏幕右边缘减面板宽度，y 应接近顶部面板高度。

**Acceptance Scenarios**:

1. **Given** 面板已关闭，**When** 用户左键点击托盘图标，**Then** 面板出现在屏幕右上角区域（x > 屏幕宽度的 3/4），且不遮挡屏幕中央
2. **Given** 面板已打开，**When** 用户再次点击托盘图标，**Then** 面板收起
3. **Given** 运行环境不支持精确定位，**When** 用户打开面板，**Then** 面板仍能正常显示（退化为合成器默认位置），不报错、不崩溃

---

### User Story 2 - 界面元素尺寸与实际缩放一致 (Priority: P2)

界面元素按屏幕真实缩放比例渲染，不出现整体放大约三分之一的情况。

**Why this priority**: 缩放不匹配会让所有元素（字宽、行高、面板宽度）视觉偏大，是本规格里最"看得见"的观感问题，但不像定位那样妨碍使用。

**Independent Test**: 在面板内渲染一个固定逻辑尺寸的参考色块，截取屏幕后测量其物理像素；物理像素 ÷ 逻辑像素 应等于屏幕真实缩放比例。

**Acceptance Scenarios**:

1. **Given** 屏幕真实缩放为 1.5，**When** 测量面板内 100 逻辑像素宽的色块，**Then** 其物理宽度为 150 像素（允许 ±1 像素误差）
2. **Given** 缩放信息无法获取，**When** 托盘启动，**Then** 按系统默认缩放运行，不改变任何既有行为

---

### User Story 3 - 面板有关闭按钮 (Priority: P3)

面板标题栏右上角有一个明确的关闭按钮，点击后面板收起。

**Why this priority**: 当前只能靠点击面板外部让它失焦收起，用户不一定知道这个隐式行为。有了按钮后，"怎么关掉它"不再需要猜测。

**Independent Test**: 点击关闭按钮，面板（窗口）应不再可见。

**Acceptance Scenarios**:

1. **Given** 面板已打开，**When** 用户点击右上角关闭按钮，**Then** 面板收起
2. **Given** 用户点击关闭按钮，**Then** 托盘图标与通知管线继续正常工作（关闭按钮只收面板，不退出应用）

---

### User Story 4 - 状态与细节信息分层展示 (Priority: P3)

面板顶栏只显示运行状态，PID、端口、启动方式、令牌状态等细节集中在底栏一行，界面不拥挤。

**Why this priority**: 属于观感优化，不影响功能正确性，但直接决定面板看起来是否"像一个成品"。

**Independent Test**: 读取面板文本内容，验证顶栏只含状态文案、底栏含 PID 与端口。

**Acceptance Scenarios**:

1. **Given** DSH 由托盘启动并运行中，**When** 打开面板，**Then** 顶栏显示「DSH 运行中」，底栏显示 PID、端口、「由托盘启动」与「带令牌」
2. **Given** DSH 未运行，**When** 打开面板，**Then** 底栏显示端口与空闲状态，不显示 PID
3. **Given** DSH 为外部启动的实例，**When** 打开面板，**Then** 底栏标明「外部启动」且令牌状态为失权提示，视觉上与正常态可区分

### Edge Cases

- **多显示器**：面板应出现在托盘图标所在的屏幕。当前无法获取图标坐标，退化为出现在主屏右上角；此限制须在文档中说明。
- **顶部面板位置改变**：用户把 Plasma 面板移到底部时，右上角锚定不再贴近图标。面板仍可用，但需在已知限制中记录。
- **缩放值非整数**：真实缩放可能是 1.25 / 1.75。换算须按浮点处理，不能取整。
- **缩放读取失败**：配置文件缺失或字段不存在时，按 1.0 处理并保持现有行为。
- **定位能力缺失**：非 Wayland 会话或其合成器不支持精确定位时，退化为既有定位逻辑。
- **关闭按钮与失焦收起并存**：两者都应能收起面板，不应互相干扰（例如关闭后立刻又被某处重新显示）。

## Requirements *(mandatory)*

### Functional Requirements

**缩放换算**

- **FR-001**: 系统 MUST 在启动时读取屏幕的真实输出缩放比例。
- **FR-002**: 系统 MUST 在检测到框架报告的缩放比例与真实输出缩放不一致时进行校正，使界面元素按真实比例渲染。
- **FR-003**: 缩放校正 MUST 在进程启动阶段完成；运行期改变缩放不要求即时生效。
- **FR-004**: 真实缩放无法获取时，系统 MUST 按默认值运行且不改变既有行为。
- **FR-005**: 校正逻辑 MUST 只在检测到不一致时生效，避免在缩放本已正确的环境里引入偏差。

**面板定位**

- **FR-006**: 面板 MUST 显示在屏幕右上角区域，而不是屏幕中央。
- **FR-007**: 面板水平位置 MUST 使面板完整可见（不超出屏幕右边缘）。
- **FR-008**: 精确定位能力不可用时，系统 MUST 退化为既有定位路径，且不报错、不阻止面板显示。
- **FR-009**: 面板垂直位置 MUST 避开屏幕顶部系统面板所占区域。
- **FR-010**: 定位实现 MUST NOT 依赖托盘图标坐标（该坐标在当前平台恒为零）。

**关闭按钮**

- **FR-011**: 面板 MUST 提供可见的关闭按钮，位于标题栏右侧。
- **FR-012**: 点击关闭按钮 MUST 收起面板。
- **FR-013**: 关闭按钮 MUST NOT 退出托盘应用或停止通知管线。
- **FR-014**: 关闭按钮 MUST 与既有失焦收起行为共存，不产生冲突（关闭后不被立即重新显示）。

**信息分层**

- **FR-015**: 顶栏 MUST 只显示运行状态（含状态指示），不显示 PID、端口等细节。
- **FR-016**: 底栏 MUST 集中显示 PID、端口、启动方式、令牌状态四类细节。
- **FR-017**: 未运行状态下，底栏 MUST NOT 显示 PID。
- **FR-018**: 接管实例（外部启动）的令牌失权状态 MUST 与正常态在视觉上可区分。
- **FR-019**: 顶栏与底栏的信息 MUST 与既有控制区的状态判定保持一致，不出现两处结论矛盾。

### Key Entities

- **显示缩放**：屏幕真实输出比例（浮点）。来源为桌面环境的输出配置；用于校正框架报告的偏差。
- **面板位置**：面板左上角的屏幕坐标。来源为锚定策略与边距计算，而非窗口移动请求。
- **面板状态摘要**：顶栏显示的状态短语（未运行 / 运行中 / 启动中 / 停止中 / 失败）。
- **面板详情行**：底栏显示的细节集合（PID、端口、启动方式、令牌状态）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 1.5 倍缩放的屏幕上，面板内 100 逻辑像素的元素实测为 150 物理像素（±1 像素）。
- **SC-002**: 面板打开后，其水平位置处于屏幕右侧四分之一的区域内（而非居中）。
- **SC-003**: 点击关闭按钮后面板在 200 毫秒内不可见。
- **SC-004**: 面板底栏能完整展示 PID、端口、启动方式、令牌状态四项，且不换行截断。
- **SC-005**: 定位与缩放能力都不可用的环境下，面板仍能正常打开与关闭（功能不退化）。
- **SC-006**: 既有测试基线（Python 224 / 插件 131 / 自检 10）全部保持通过。

## Assumptions

- 目标环境为 KDE Plasma 6 / Wayland（当前开发机），其它桌面环境按退化路径处理。
- 屏幕缩放值可从桌面环境的输出配置中读取；读不到时按默认值处理。
- 面板固定为单栏宽度、贴右上角；不实现"记住用户拖动后的位置"（YAGNI，用户未提该需求）。
- 托盘图标坐标在当前平台不可得，本规格接受"锚定屏幕右上角"作为等价方案，因为该用户的 Plasma 面板固定在顶部、托盘位于右上角。
- 顶栏与底栏的文案语言与现有界面保持一致（中文）。
- 本规格不改变通知投递、历史记录、会话深链等既有行为。
