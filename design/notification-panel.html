四个标签页的数据来源不同

未查看 / 已查看插件 push（spool 事件），托盘只读 工作中插件 push 状态快照，托盘本地计时 概览托盘自己采样 /proc，面板开着才采

把「概览」放在托盘侧而不是插件侧，是因为它要在 DSH 卡死、甚至没起来时也能用——那正是最需要看进程的时候。

工作中：怎么知道谁在跑

  • 插件在会话状态变化时写一条状态快照（谁在跑、第几轮、轮次开始时刻、当前工具），变了才写。
  • 时长由托盘本地每秒累加，插件不必高频心跳——省 IO，也不会让时长卡顿。
  • 有会话在等你（审批/提问）时，圆点转琥珀色并标「等你回答」；这类会话不会出现在「工作中」以外的地方。
  • 点任一行 → 直接打开该会话。

概览：采样的三个硬约束

  • 线程安全：采样在固定后台线程，不阻塞 Qt 事件循环；面板关闭即停。
  • CPU 需要两次采样：单次读数只能拿到累计 jiffies，百分比必须用两次间隔求差，所以第一次打开面板时首行 CPU 显示「—」而不是 0%。
  • 不引入 psutil：Linux 读 /proc/<pid>/stat 与 status；Windows 走 CIM。
